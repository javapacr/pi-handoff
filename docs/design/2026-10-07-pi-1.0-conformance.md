# pi 1.0 extension-standards conformance pass

**Status:** DONE 2026-10-07 on branch `chore/pi-1.0-conformance` (cut from
`main@f0bc7f3`). Runtime: pi 1.0.4.

This brings the extension in line with the pi 1.0 extension docs. It is not an
API migration: at `f0bc7f3`, `tsc --noEmit` and the smoke suite already passed
against both 0.84.1 and 1.0.4. Sources: `<pi>/docs/extensions.md` ("Respect
the runtime lifecycle", "Tool exposure", "Errors and cleanup"),
`<pi>/docs/packages.md` ("Declare dependencies"), and
`dist/core/extensions/types.d.ts`.

New smoke checks cover these:

- the manifest declares host-provided packages as peers with `"*"` and none as dependencies;
- the API hooks are exactly `agent_settled`, `session_shutdown`, and `session_start` (no `agent_end`);
- calling `session_shutdown` twice does not throw;
- the `continue` tool has `exposure` and `annotations` set.

Check that the host-provided warning is gone. `pi -e <dir>` does **not**
trigger the check: CLI `-e` paths carry no `packageRoot` metadata. Load the
worktree as a local *package* from a scratch agent dir instead:

```sh
A=$PI_CODING_AGENT_DIR/tmp/pih-warncheck; mkdir -p "$A"
printf '{"packages":["%s"]}\n' "$PWD" > "$A/settings.json"
PI_CODING_AGENT_DIR=$A pi --print ok 2>&1 | grep -i host-provided   # empty after the fix
```

Before the fix, this printed the warning for the worktree `package.json`.
After the fix, it prints nothing.

Check live registration: a probe extension loaded with `-e` in the same
scratch dir reported `active=true exposure=model-only` and the four
annotations on `session_start`.
